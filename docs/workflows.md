# 笔记与 AI 工作流

## 记录类型

| 内容 | 类型 | 推荐位置 |
|---|---|---|
| 原始想法、尚未分类的输入 | `capture` | `01_收集` |
| 一个明确的下一步动作 | `task` | `02_行动/任务` |
| 多个动作共同达成的成果 | `project` | `03_目标与项目/项目` |
| 项目的规划、调研、方案文档 | `project_doc` | `03_目标与项目/项目文档` |
| 一章学习及实践证据 | `learning` | `04_学习/主题` |
| 职位和面试准备 | `interview` | `05_求职` |
| 一道编程题 | `exercise` | `06_刷题` |
| 每日事实和输出 | `daily` | `07_回顾/每日记录` |
| 每周复盘 | `review` | `07_回顾/周回顾` |

样例中的八类模板来自当前实际使用的模板结构。`project_doc` 在工作流说明中单列，可沿用已有项目文档格式；这版没有添加第九个正式模板。

## 章节学习

确认资料与章号，先保存实际回答、代码和运行结果，再整理概念、易错点、复习问题和笔记。`mastery` 依据展示出来的证据判断，未实践的部分标为待验证。笔记完整与实际掌握分别记录。

## 项目与任务

新建前先搜索相关项目。已有主项目时，把规划文档链接到它的子文档小节；记录 `parent` 链接。需要执行的动作再创建 task，不把每个讨论点都变成任务。

## 回顾

读取这次相关的任务、项目和每日记录，按实际完成与输出回顾。延期原因依据记录分析，缺少日期和耗时证据时保留待确认。

## 写回规则

先读原文和模板，再局部编辑；保留未知字段、原始回答、来源和历史状态。写后重读，核对内容、链接和是否产生重复记录。发现并发修改时重新读取并合并。

这些规则可以写入 ChatGPT 的协作指令，见 [操作约定](../prompts/obsidian-assistant.md)。模板和提示词不会自行建立 MCP 连接。
