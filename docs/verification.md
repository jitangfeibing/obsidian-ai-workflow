本轮将早期接入教程仓库补齐为可复用系统。原用户此前确认基础方案在自己的 Windows 环境可用；此事实不能替代新机器的账号授权、界面和隧道验收。

### 本轮自动检查

- 61 个安装白名单文件与 SHA-256，11 类模板、Base 视图引用、Markdown 链接、空白库无个人业务记录、Windows UTF-8 BOM/CRLF。
- 项目创建与 parent、四类转换、原文/未知属性保留、重分类、移动失败与重复触发保护。
- 首页真实类型/归档/模板筛选、日期边界、草稿与写入失败保留。
- 项目和多层文档、状态/摘要、并发保护、循环与归档、历史完成时间。
- 学习创建、主题、重复保护、日期、原始证据、不推断掌握程度和复习归档。
- 内置分类菜单写回、范围过滤、已转换记录拒绝；计时新目录创建、模板与库外记录排除、恢复重试。
- 安装计划不落盘、全新安装、重复安装、受管升级、编辑页面和 data.json 保留、回退拒绝覆盖新修改、较新插件不降级、越界路径拒绝。
- 可配置 profile/代理/健康端口、直连和旧配置兼容；隧道诊断脚本仅本地获取凭证。
- 备份/恢复核心与任务定义模拟检查。

本地执行环境为 Linux + PowerShell 7.6.7、Node 和 Python；Windows PowerShell 5.1 的原生检查由仓库 CI 执行，其结果以该次 GitHub Actions 为准。

交接后已在 Windows 上使用 Windows PowerShell 5.1 复测语法、客户端参数、备份恢复与任务定义；四组项目插件测试及 16 项工具测试通过。安装与回退检查在独立临时目录运行，因真实 Obsidian 保持打开，仅在这些测试中模拟程序已关闭；原生关闭检测本身已确认会拒绝安装。由 Git 暂存树导出的 ZIP 也通过文件校验和全新安装、重复安装、升级回退及用户内容保护检查。

### 每位新用户仍需实际执行

Obsidian 加载/信任自定义插件、核心 Bases、具体页面点击；MCP 插件安装和认证；本人组织/工作区、隧道、Runtime Key 和 ChatGPT 真实读/创建/回读；后台自启在重登录后的持续运行；实际备份/恢复和剪藏浏览器导入。

这些步骤列在 [迁移手册](codex-migration.md)。源码/文件级检查通过不会自动完成账号界面授权，也不会使关机的本机库继续在线。
